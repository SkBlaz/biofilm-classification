# MicroICS

MicroICS is a tool that links descriptors derived from 2D or 3D biofilm images to biological questions of interest using machine learning algorithms. These descriptors are referred to as features, following standard terminology in the field, which is used consistently throughout the tool.

MicroICS is organised into three interoperable modules that can be run together as a pipeline or independently:
- Feature generation computes biofilm descriptors across several families: basic biofilm metrics, 3D object features, advanced 3D geometry, substratum (2D) features, intensity-based metrics, geometry and texture, and multi-threshold (ML-ensemble) features.
- Model training trains and compares machine learning classifiers on these features, identifies the features that best discriminate the groups of interest, and saves the resulting models.
- Inference applies a saved model to new, unseen images to predict their class labels.

When the three modules are run consecutively, they form a complete pipeline: feature generation computes the features, model training builds a classifier from them, and inference applies that model to predict the biological group of previously unseen images. The modules can also be used independently, for example, feature generation on its own to compute biofilm descriptors for analyses other than machine learning, or model training with externally derived (non-MicroICS) features included alongside those generated by the tool.

MicroICS can be installed and run in two ways: from the command line, as described below, or via Docker Desktop, which requires no command-line setup and is documented in the accompanying guide (resources/installation_and_running_MicroICS). The resources/ folder also provides step-by-step manuals for running the individual modules, descriptions of their outputs, and other useful information.

## Standalone web application

The production image contains the web interface, MicroICS source, Python, and the complete scientific environment. Docker is the only host-side runtime requirement; Python, Conda, Git, Docker Compose, repository mounts, and Docker-socket access are not required to run a built image.

Build and start it from a source checkout:

```bash
docker build -t microics .
mkdir -p "$HOME/Desktop/MicroICS-results"
docker run --rm --user "$(id -u):$(id -g)" -e MPLCONFIGDIR=/tmp/microics-matplotlib -p 8765:8765 --mount "type=bind,source=$HOME/Desktop/MicroICS-results,target=/data" microics
```

Open <http://localhost:8765>. Jobs, uploads, and results are stored in the chosen host folder under `jobs/<job-id>/`; completed results can also be downloaded as a ZIP streamed directly to the browser. See [RUN.md](RUN.md) for Windows PowerShell commands, recovering existing Docker data, and cleanup.

The application stores each run under `/data/jobs/<job-id>/` and never needs access to host filesystem paths. The image accepts `.tif` and `.tiff` uploads and compatible pre-generated `.tsv`/`.txt` feature tables.

For convenience on Unix-like development systems, `bash run_gui.sh` builds and starts the same standalone image. `docker-compose.yml` is an optional equivalent for development; the application does not invoke or depend on Compose.

## Workflows

The GUI supports the real MicroICS stages:

1. generate features from labelled or unlabelled images;
2. train one learner or compare all learners from a complete feature table;
3. run inference from uploaded images or a compatible precomputed data file using models from a completed training job;
4. run labelled feature generation, training, and image inference together.

Before generating features, enter the X, Y, and Z voxel dimensions from the microscope metadata. Training defaults to the published ordinary stratified benchmark protocol. In **Train models**, optionally choose date, well, or imaging position as the replication unit to keep related samples together during cross-validation and estimate performance on independent groups.

## Development validation

With the Python dependencies installed locally, run:

```bash
PYTHONPATH=src python run_tests.py
python -m ruff check .
python -m ruff format --check .
```
